# P7実装契約

## 公開入口

P7は通常の `/` で有効になり、既存リンクの `?p7=1` も同じP7本体を開く。P3の試作は `?p3=1` の明示入口へ移し、P7以外ではP5/P6で追加した公開状態とE2Eフックを変更しない。P7の表示は横画面を前提とし、縦画面では既存の向き案内を優先する。

## シミュレーション契約

P7は `P5StageData` を面ごとに定義し、そこから`P5SimulationScenario`を構成して同一シミュレーションを構成する。面データには初期配置、開始位置、囲い、地形、世界境界、`rulesetId`、完了条件を含める。シミュレーションと面の表示で別の配置値を持たせない。シナリオは次を定義する。

- 臆病種、追従種、危険種の生成数
- 必須経路（安全・速い）
- 経路を通る必要がある動物の種類
- 必須イベント（誘導音による追従開始、威嚇音による危険種の受容）
- 必須イベントの順序（面4では誘導音の後に威嚇音）

`status = completed` は、すべての生成対象を収容し、危険種が存在する場合は隔離し、必須経路と必須イベントを満たした場合だけ設定する。経路に動物の種類が指定されている場合は、該当する種類の実際の通過イベントを確認する。イベント順序が指定されている場合は、履歴上の順序も確認する。既定シナリオの必須条件は空であり、P5の既存挙動を維持する。

すべての個体を収容した時点で必須条件が不足している場合は、`failed / objectivesIncomplete`へ遷移する。未達条件は結果画面へ表示し、現行ルールのクリア、記録更新、次面解放、第4の動物ゲートには反映しない。これにより、条件を達成できる個体や合図がなくなった後も`active`のまま残ることを防ぐ。

## 進行 API

画面内の `window.__OITATE_P7__` は診断用の公開口で、次を提供する。

- `getState()`：面、状態、メニュー、結果、保存進行を取得
- `retry()`：現在面を再試行
- `openMenu()`：面選択を表示

`e2e` は開発ビルドかつ `?p7-e2e=1` の場合に限り公開する。本番ビルドには完了リプレイや条件不足リプレイを出さない。

## 保存契約

保存キーは `oitate:p7:progress:v1`のまま維持し、ペイロード版を2へ更新する。版2にはトップレベル`rulesetId`として現行の`P5_STAGE_RULESET_ID`を必須化し、欠落・不一致の場合は版2の`completedStageIds`、`unlockedStageIds`、`fourthAnimalGate`、`records`を現行として採用しない。面ごとに標準・補助あり・練習の記録バケットを分け、現行記録へ`rulesetId`を付ける。旧形式（版1）の面単位記録は読み込み時に読み取り専用の`legacy`へ移し、対応するモードを補完する。旧クリアによる面アクセスは維持するが、現行ルールのクリア数、最高記録、記録更新、第4の動物ゲートへは加算しない。読み込みだけでは保存を書き換えず、次の正常な現行保存で版2を書き出す。未知の値や破損値は無視して初期状態へ戻す。

## UIと回帰

- 面選択では、練習と1面を初期解放し、クリア後に次面だけを解放する。
- 結果画面では、得点、評価、4項目の内訳、次回助言、面別最高記録を表示する。
- 同じ面・モードに現行記録と旧版`legacy`記録がある場合は、結果画面と面ステータスへ両方を併記する。片方だけの場合は、その記録だけを表示する。
- 標準・補助ありの音・振動設定はP6と共通利用する。音・振動を無効にしても進行不能にならない。
- 第4の動物はゲート表示だけを実装し、通常の1.0プレイ対象へは追加しない。
- 面4の面選択とプレイ中の目的表示は、保護対象6体と危険種1体の収容・隔離を同じ文言で示す。
