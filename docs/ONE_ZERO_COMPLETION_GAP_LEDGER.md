## 1. 状態の定義

- `DONE`: 実装と必要な証拠がそろっている。
- `VERIFY`: 実装は存在するが、人手受入、初見、実機、最終照合などの証拠が不足している。
- `TODO`: まだ作成・取得・実施していない。
- `DROPPED`: 1.0では意図的に行わない。未完成とは扱わない。

自動CIの成功は、手動受入、初見理解、実機性能、公開品質の代わりにしない。

## 2. 1.0の正式な実機基準

ユーザー判断により、**OITATE 1.0の実機受入はiPhone 17 Pro 1台で実施する。**

- 必須端末: iPhone 17 Pro
- 必須ブラウザ: Safari
- 基本向き: 横画面
- iPhone 11 Pro: `DROPPED`（1.0必須検証対象外）
- iPad Pro 2018: `DROPPED`（1.0必須検証対象外）
- PC: `DROPPED`（1.0必須検証対象外）

対象外3環境を未確認のため1.0未完成とは扱わない。ただし、それらを「動作確認済み」「正式対応済み」とも表現しない。将来確認する場合は1.0後の追加証拠とする。

## 4. すでに完成とみなす項目

### 4.1 ゲームの中心
- 主人公の位置で臆病種を動かす接近圧力。
- 誘導音で追従種を導く。
- 威嚇音で危険種の注意を主人公へ向ける。
- 3種類の専用囲い。
- 危険種の索敵、追跡、狙い、飛びかかり、回復。
- 初回攻撃後の救助、救助期限、再攻撃失敗。
- 安全経路と速い経路。
- 群れ、緊張、混乱、入口予約、後退・再試行。

### 4.2 1.0の内容
- 練習または段階的説明。
- 6ステージ。
- 面ごとの中心概念と完了条件。
- 面4の誘導音→威嚇音の順序条件。
- 面5・面6の動物種別経路条件。
- 進行保存、面別記録、再読み込み復旧。
- 6面クリア後の第4動物候補ゲート。

第4の動物は「条件を満たした場合のみ追加」のため、現時点で通常面へ入れていないことを未完成とは扱わない。

### 4.3 得点・結果・補助
- 100,000点。
- 安全40,000 / 統率25,000 / 危険管理20,000 / 時間15,000。
- S〜C評価。
- 称号と次回助言。
- 標準、補助あり、練習の記録分離。
- 音、振動、操作部品サイズなどの設定基盤。

### 4.4 技術・公開基盤
- Vite / TypeScript / Three.js基盤。
- GitHub Actionsによる型確認、単体、build、ブラウザ試験、公開監査。
- ChromiumとWebKitの自動確認。
- GitHub Pagesへの`dist`自動公開。
- JS初期化失敗時に真っ白画面へしないbootstrap表示。
- 公開ビルドの容量・参照・依存ライセンス監査。
- 再現可能な実ゲーム画面3枚の自動撮影。

### 4.5 直近の不具合修正
- カメラ旋回時の進行方向ずれ。
- 収容後の羊の高速振動。
- 羊が片側回避に失敗したまま停止する問題。
- ワールド端の補正を「移動成功」と誤判定する問題。
- 上記の回帰試験。

## 5. VERIFY: iPhone 17 Proで確認する内容

現在公開版を基準に、以下を一巡する。

### 5.1 操作・表示・復帰
- 横画面起動。
- 移動しながらカメラを回しても進行方向が一致する。
- 誘導音、威嚇音、取消、同時入力。
- 入力中断後に押下状態が残らない。
- 縦横回転、タブ移動、ホーム復帰。
- 音あり・音なし。
- 10分連続プレイ。

### 5.2 直近不具合の再発確認
- 収容後の羊が高速で震えない。
- 羊が障害物・他個体・ワールド端で停止し続けない。
- カメラ旋回後に主人公の進行方向が不自然にずれない。
- Safariで真っ白にならない。

### 5.3 P1〜P7統合確認
過去段階を別々にやり直すのではなく、現在の統合版で旧条件へ証拠を対応付ける。

- 移動とカメラを自力で扱えるか。
- 主人公の位置と臆病種の移動方向の関係を説明できるか。
- 3種類の違いを説明できるか。
- 危険種の攻撃予告を事前に認識できるか。
- 救助成功・失敗の理由を説明できるか。
- 安全経路と速い経路を発見または利用できるか。
- 失敗後に次へ変える行動を一つ説明できるか。
- 結果画面から得点改善方法を理解できるか。
- 再挑戦で得点、評価項目、時間のいずれかが改善するか。
- 練習から6面クリアまで進行不能がないか。
- 保存、再読み込み、復帰が成立するか。

当初の人数目標は設計上の参考として残すが、1.0の実機受入端末条件とは分離する。
